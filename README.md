# Status CQA

**Команда Status**. Участники — **Amir Romanov** и **Sulukhan Aizharykova**.

Прототип для хакатона Freedom Broker оценивает работу оператора по восьми критериям, показывает обоснования со ссылками на реплики и сохраняет историю пересмотра. Интерфейс доступен на русском, казахском и английском. При первом запуске выбран чек-лист **1.2.1**.

## Результаты хакатона

Файлы можно открыть прямо на GitHub.

| Набор | Записи | Результат |
| --- | ---: | --- |
| [DEV](results/dev/results.json) | 65 | 65 оценок |
| [PROD](results/prod/results.json) | 10 | 10 оценок |

Для просмотра готовых оценок достаточно открыть JSON на GitHub. При подготовке итоговой выгрузки для одного английского чата потребовался отдельный запуск Qwen без режима рассуждений.

В каждой успешно обработанной записи есть ответы по критериям, обоснования, номера реплик и итоговый балл. Грубое нарушение отмечается отдельным флагом. Статус `ok` означает, что оценка получена. Точность относительно экспертных эталонов определяют организаторы.

## Запуск на своём компьютере

Скачайте проект через **Code → Download ZIP** и распакуйте его или клонируйте репозиторий. Откройте терминал в папке с этим README. Нужны Python 3.11 или новее и интернет для установки зависимостей.

**Windows, PowerShell**

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.lock.txt
.\.venv\Scripts\python.exe -m cqa.web
```

**macOS и Linux**

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.lock.txt
.venv/bin/python -m cqa.web
```

Оставьте терминал открытым и откройте [локальный интерфейс](http://127.0.0.1:8787/). На чистой установке список диалогов пуст. В разделе «Диалоги» нажмите «Загрузить диалоги», выберите [учебный разговор](examples/dialogue.json) и подтвердите загрузку. Вы увидите роли, время и текст пяти реплик. Здесь же можно загрузить JSON с набором разговоров. Для загрузки и редактирования чек-листов модель не требуется.

## Новая оценка с Qwen

1. Запустите **Ollama 0.40.15** на машине, подходящей для Qwen3 32B, и загрузите модель командой `ollama pull qwen3:32b`. Движок проверяет версию сервера и тег модели.
2. В [профиле модели](config/settings.product.json) указан локальный адрес `http://127.0.0.1:11435`. Если Ollama работает на том же компьютере на обычном порту 11434, задайте для `base_url` значение `http://127.0.0.1:11434`. Если модель уже доступна через локальный туннель на 11435, используйте исходный профиль.
3. Откройте второй терминал в папке проекта. В Windows выполните `.\.venv\Scripts\python.exe -m cqa.tokenizer_setup`, в macOS и Linux — `.venv/bin/python -m cqa.tokenizer_setup`. Команда скачает токенизатор Qwen (около 11 МБ) и проверит контрольную сумму.
4. В карточке разговора нажмите «Оценить диалог», выберите версию **1.2.1** и нажмите «Начать анализ». Откройте готовую оценку и нажмите на номер реплики в обосновании.

Чтобы проверить гибкость системы, откройте «Чек-листы», измените формулировку одного критерия, сохраните новую версию и оцените разговор ещё раз. Для проверки апелляции выберите «Оспорить оценку» в карточке критерия. После решения проверяющего откройте сравнение «До / после апелляции». Исходная оценка остаётся в истории.

При новой оценке Qwen начинает с включённым режимом рассуждений. Если Ollama сообщает, что лимит ответа исчерпан, а итоговый текст пуст, приложение само отправляет тот же запрос один раз с выключенным режимом рассуждений. Это правило действует и для пакетной команды PROD. В истории оценки сохраняются запросы и ответы обеих попыток. Время ожидания ответа на одну попытку — до 300 секунд. Для оценки нужен доступный сервер модели.
